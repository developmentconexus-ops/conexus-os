# apps/keycloak-theme

The Keycloakify sign-in theme for the `r1f` realm. It uses the brand from `packages/brand`. [`README.md`](README.md) covers the local preview and the jar build.

## Traps

- Keycloak sends a CSP that blocks inline styles, so a `style` attribute silently never applies. Size and color go in a class in `src/styles.css` or `packages/brand`.
- Six pages have a Conexus layout in `src/login/pages/`. Every other page id falls through to Keycloakify's default in `src/login/KcPage.tsx`. A new custom page needs its `case` there.
- Keycloak messages carry HTML. Render them only through `kcSanitize`. The realm serves `pt-BR` only.
- The theme has its own `package.json` and `package-lock.json`, with `keycloakify` 11.16.0. Its dependencies are not in the root lock. `src/kc.gen.tsx` is generated by Keycloakify. Never edit it.

## Verify

```bash
npm run keycloak-theme:check   # typecheck and Vite build; needs the theme's own node_modules
npm run web:style:check        # no raw hex, only the three brand fonts
node --test tests/implementation/brand-wordmark-csp.test.mjs
```

CI does not build this theme. The full jar needs Maven and a JDK; see the README.
