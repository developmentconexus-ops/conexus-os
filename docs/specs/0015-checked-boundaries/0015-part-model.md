## Summary

Part 5 ports six model functions, parses model rows, and puts the three model tables under the split wall: a `reader` policy on two of them (the sharing history has none), the one `command` policy, and the column grant `UPDATE (kind, secret, updated_at)` on `model.model_account`. It declares the model account routes and moves their web calls to the shared contract. The four argument upsert becomes a direct write, and a shared credential refresh after sharing is withdrawn is tested. All eleven routes become operations. A run reads a credential it holds on the command role after `admitRun`, filtered by the run from the proof, and persists a refresh through the executor system transaction even if the run ends or the Hub stops. The current store calls the upsert with four arguments, so PostgreSQL uses the null defaults for sharing and actor. `apps/hub/src/builder/model-account-store.ts:45-47`; `apps/hub/migrations/0044_model_account_sharing_history.sql:35`.

Today every model statement runs as `hub_runtime` on `runtimePool` through six `SECURITY DEFINER` functions (`apps/hub/src/builder/module.ts:125-131`). After this part no model statement runs outside `transaction`, `read` or `system`. The model owner stays in `apps/hub/src/builder/`: architecture section 11 moves model accounts to the core in a later wave (`architecture.md:389`), and this part neither moves them nor adds an import that move would have to undo.

**Module shape.** Chosen by a two design bakeoff (Opus and Sonnet candidates; HQ synthesis in the
study notes, `arena/synthesis.md`). One deep module owns the three model tables, the envelope and every
transaction entry, so the sealed value never leaves one file. A module is a function that returns a
frozen object, a named top level function is a declaration, and a function that takes more than two
parameters takes one object ([code](../../development/codebase-principles.md#3-functions)).

```ts
// builder/model-account/providers.ts: pure, imports no Hub module
export const MODEL_PROVIDERS = { /* per provider: name, router prefix, lawful kinds, offers, key shape, models */ } satisfies Record<ModelAccountProvider, ProviderEntry>
export type Lawful = { [P in ModelAccountProvider]: Readonly<{ provider: P; kind: (typeof MODEL_PROVIDERS)[P]['kinds'][number] }> }[ModelAccountProvider]
// derived from the table's literal kind tuples (anthropic api_key|oauth, openai-codex oauth, google-ai-pro google_ai_pro); row parsing uses the same table
export type ModelRoutes = { readonly [P in ModelAccountProvider as (typeof MODEL_PROVIDERS)[P]['routerPrefix']]: ModelRoute<P> }   // keyed by the model id prefix, exhaustive, built with satisfies

// builder/model-account/accounts.ts: the owner of model.*; the only file that holds the envelope
export function createModelAccounts(deps: Readonly<{ database: Database; envelope: SecretEnvelope; ownerId: string }>): ModelAccounts
type ModelAccounts = Readonly<{
  standing(accountId: AccountId): Promise<ModelStanding>            // one reader read, every provider; no secret
  write(input: Readonly<{ accountId: AccountId; credential: Lawful; secret: string }>): Promise<void>
  connect(input: Readonly<{ accountId: AccountId; credential: Lawful; secret: string }>): Promise<'connected' | 'failed'>
  readDefault(accountId: AccountId, role: ModelRole): Promise<string | null>
  usable(accountId: AccountId, provider: ModelAccountProvider): Promise<boolean>     // the pre-run check: the select read, opens the secret, keeps nothing
  select(run: HeldRun, provider: ModelAccountProvider): Promise<HeldAccount | null>   // today's usable, same admission
}>
type OwnAccount = Readonly<{ state: 'absent' }> | Readonly<{ state: 'connected'; kind: ModelAccountKind }>
type ModelStanding = Readonly<Record<ModelAccountProvider, Readonly<{ own: OwnAccount; shared: boolean }>>>
type HeldRun = Pick<RunContext, 'builderRunId' | 'accountId'>
type HeldAccount = Readonly<{
  modelAccountId: ModelAccountId; credential: Lawful; secret: string; run: HeldRun
  read(): Promise<HeldAccount | null>            // readHeldCredential: admitRun, the row the run recorded
  persist(secret: string): Promise<boolean>      // persistHeldCredential: system('builder-executor'), with credential.kind; false means the row is gone or its kind changed
}>
// private to accounts.ts: readById(proof: Admitted<RunScope>, ...) and rewrite(proof: Admitted<SystemScope<'builder-executor'>>, ...)
```

The held handle carries its run, so the provider routes take it whole: `take(held)`, `hold(held,
tokens)` and `track(key, held)`, in place of `take(account, run)`, `hold(run, id, tokens)` and
`track(key, id)`. That changes `ModelRoute.take` (`apps/hub/src/builder/model-routing.ts:18`) and its
three implementations, `createTokenHolds` (`apps/hub/src/builder/oauth-holds.ts:29,34`) and the Google
write back (`apps/hub/src/builder/google-ai-pro/write-back.ts:26`) in the same commit;
`createTokenHolds` and `createRefreshWriteBack` lose their store dependency. `connect` is the one place
that turns a refused credential write (`ACCOUNT_INACTIVE`, `ACCOUNT_NOT_FOUND`) into `'failed'`; the
three login ports return that state and catch nothing themselves
([code](../../development/codebase-principles.md#6-errors)). `standing` replaces `connection`,
`hasShared` and the MDL-01 installation scope. The pre-run `check` uses `usable`, which runs the same admitted read as `select` and opens the secret, so a row whose secret does not open still fails before the run, as today; `accountFor` splits into `check` (`usable`, no run) and `call` (`select`, with the run). Routing takes `Pick<ModelAccounts, 'usable' | 'select'>`.

`MODEL_PROVIDERS` replaces the fourteen places and the three copies of the kind union the study
counted (`model-offers.ts` is not created; `ANTHROPIC_KEY_SHAPE` and `GOOGLE_AI_PRO_MODELS` move into
the table, which avoids an import cycle with the provider files). `takeFrom` is an exhaustive switch
over `Lawful`, so `isAnthropicKind` goes and an unlawful (provider, kind) pair read from a row is an
internal fault at the parse. The routing map is keyed by `MODEL_PROVIDERS[p].routerPrefix` (the prefix of the model id, `openai` for `openai-codex`), derived from the table, so `routes[providerOfModel(modelId)]` finds the account provider (`apps/hub/src/builder/model-routing.ts:34,45-58`; `apps/hub/src/builder/module.ts:150-154`); a test asserts `openai/<model>` selects the `openai-codex` account. `builder/model-accounts.ts` keeps the eleven routes and loses the size
suppression (`:121`); its default thinking level arrives from `module.ts`, so no model file imports
the harness (`:8`).

Not chosen: one `holdCredential` that admits the run, picks the paying row and records it in one
transaction (Opus candidate). It changes the decided `select` admission (section 9), the error code of
a closed run and every PostgreSQL fixture of section 7, with no seen failure behind it.

**Types.** Inputs are `AccountId` and `ModelAccountId` from the contract, the new closed schemas `ModelAccountProvider` (`'anthropic' | 'openai-codex' | 'google-ai-pro'`) and `ModelAccountKind` (`'api_key' | 'oauth' | 'google_ai_pro'`, the values of the database check) in `packages/contract/src/model-account.ts`, as `ConnectorId` is one list in `packages/contract/src/connectors.ts:11`, and `ModelLoginId` (`packages/contract/src/ids.ts:34`, built for this and unused). `AccountId` no longer comes from `identity-access/current-session.ts` (`model-accounts.ts:12`). Rows are read with `tx.rows` and `tx.maybe` ([code](../../development/codebase-principles.md#5-boundaries)). `HeldAccount` keeps its opened `secret` (`model-account-store.ts:8`). The five rows of the model owner in the unparsed rows census (`contracts/technical/census-boundaries.json:3-7`) leave it.

## 4. The split wall for the model tables

All three model tables have `ENABLE` and `FORCE ROW LEVEL SECURITY` and the one policy `command ... TO hub_command USING (true) WITH CHECK (true)`. None of the three is on the administrator reach list, so none has a `reader_admin` policy, and the grantee has no reader branch (admission child, section 4.2, rules 4 and 5).

| --- | --- |

| `model.installation_default` | `A IS NOT NULL` |

## 5. The held credential and the executor

`select` selects the caller's own row before a shared row. The run records each model account that pays for a call. `apps/hub/src/builder/model-account-store.ts:36-39`; `apps/hub/src/builder/model-routing.ts:64`. A held OAuth refresh reads the held row on the command role after `admitRun`, filtered by the run from the proof. It then persists the new sealed secret through the executor system port. A spent refresh token can be the only copy. The write must finish even after the run ends or sharing closes. Google can write back when its proxy instance stops, during idle reap, or on Hub close, after the run is `INTERRUPTED`. Its tracked row id also uses the system port. The current callback writes by id. `apps/hub/src/builder/google-ai-pro/write-back.ts:21-25`.

Use `take(held)`, `hold(held, tokens)` and `track(key, held)`, where the held handle carries `run: HeldRun`, the `builderRunId` and `accountId` of the `RunContext` (`apps/hub/src/builder/run-context.ts:7`). Routing obtains both from the request context through `requireRunContext`. `apps/hub/src/builder/model-routing.ts:62`; `apps/hub/src/builder/model-routing.ts:18`; `apps/hub/src/builder/oauth-holds.ts:10`; `apps/hub/src/builder/google-ai-pro/write-back.ts:17`. The run controls the held read and the tracking. The persisted write uses the system proof, even if the run's account loses Project access or the run ends. A new call still selects under current sharing and can return null for a non owner. `apps/hub/src/builder/model-routing.ts:55-60`. The held read of a run whose account lost Project access is refused by `admitRun` and becomes `BUILDER_MODEL_NOT_SELECTED`.

**The ports.** The umbrella's two ports are the methods of the held handle: `held.read()` is `readHeldCredential` and `held.persist(secret)` is `persistHeldCredential`. `read` is `withRun` with the account actor around the private `readById`, returns null for a refusal of `ADMISSION_REFUSALS`, and opens the secret after the transaction ends. `persist` seals before it opens `system`, as `createConnection` seals before its transaction, and returns false when the row is gone or its kind changed. `oauth-holds.ts` and the Google write back take the held handle where they took `Pick<ModelAccountStore, 'readById' | 'rewrite'>` (`apps/hub/src/builder/oauth-holds.ts:20-21`; `apps/hub/src/builder/google-ai-pro/write-back.ts:13`; `apps/hub/src/builder/anthropic/credential.ts:33-39`; `apps/hub/src/builder/openai-codex/credential.ts:40`).

**Concurrent writers.** A write back is by id and the later commit wins. Two runs do not refresh one row at once, because `createTokenHolds` keeps one pending refresh per row in memory (`apps/hub/src/builder/oauth-holds.ts:26`) and one Hub holds the instance lock (`apps/hub/src/platform/lifecycle.ts:67`). A person's new login that commits during a run's refresh is replaced by the refreshed older chain (study spike `22-refresh-race`). No compare and swap: the window is one HTTP call and no failure has been seen (HQ, 2026-10-06).

**Each waiting run is admitted.** `createTokenHolds` keeps one pending refresh per row, but every caller runs its own `held.read()` (its own `admitRun`) before it awaits or starts the shared refresh, and a caller whose read is refused gets `BUILDER_MODEL_NOT_SELECTED` without receiving the pending result (`apps/hub/src/builder/oauth-holds.ts:26,28-49`). Test: run X allowed and run Y revoked while X's refresh is pending; Y fails, X persists.

**Crash limit.** If the Hub is killed after the provider answers and before the write commits, the row keeps the old sealed secret and the new refresh token is lost, as today. The person connects again. A Google proxy's refreshed record is lost the same way (study spike `23-crash-window`).

The secret read of `select` moves to a command transaction after `admitAccount`, as the held read already is (Review A, F4).

The installation default read moves from `builder/module.ts` to the model store, and the store takes `database` (`data`, `apps/hub/src/builder/module.ts:96,125`), not the pool. `runtimePool` leaves the model owner. No Project purge port is needed because the model tables have no Project id or Project foreign key. `apps/hub/src/builder/module.ts:125-131`; `apps/hub/migrations/0033_model_account.sql:21-38`.

## What breaks the premise

- A credential refresh that must run under the run's account instead of the executor: the design assumes the system write by id is the only way to keep a spent refresh token.
- A command that needs `UPDATE` on `owner_account_id`, `sharing`, `provider` or `model_account_id`, or a person who needs to read `secret` on `hub_reader`: the design assumes the column grants and the command role's proof hold them.
- An unported caller of a `model.*` function that the census missed, or a model row that must exist before its owner account.
- A model call per step whose `select` read and `record` (two admissions, each with locks) measurably slows a Builder turn: the design assumes the Account `FOR SHARE` is cheap beside the model call.
