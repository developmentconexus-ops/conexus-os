# 4C — Cross-Layer Decision Methodology Rule

> **Status:** OPERATOR-RATIFIED METHODOLOGY RULE / ACTIVE THROUGH 4C
> **Scope:** every material decision discovered while realizing the browser Product, including frontend, backend, Product logic, wire/API, state, data, authorization, security, source/Git, runtime or persistence implications.
> **Authority posture:** methodology/governance only. This file creates no Product operation, owner, Permission, schema, route, runtime or implementation authority.

The operator explicitly requires that decisions discovered during the frontend stage use the same DevelopmentConexus Engineering Method rather than being solved by UI convenience, framework convention or local implementation taste.

## Binding decision loop

```text
real human need / accepted Product journey
→ recover current repository authority
→ state the protected property and concrete consumer
→ classify known / inferred / unknown / deferred
→ create the smallest falsifier / RED when mechanically possible
→ compare real alternatives when ambiguity is material
→ use bounded current reference research only where it can change the decision
→ Global Maximum + YAGNI adjudication
→ identify exact semantic owner / trust / Permission / state / wire impact
→ reopen only the smallest owning authority when current authority is insufficient
→ recompile only affected downstream artifacts
→ require GREEN proof
→ only then admit the UI / Screen Contract / realization consequence
```

## Cross-layer law

A frontend-discovered requirement does not become frontend authority merely because the need was first seen in a screen.

```text
frontend exposes missing backend/Product truth
-X-> invent endpoint/DTO/state in frontend
-X-> decide backend shape from visual convenience
-X-> choose runtime/library first and search for a requirement later

frontend exposes missing backend/Product truth
→ FINDING
→ smallest owning Product/wire/security/data/runtime stage
→ same Decision Loop / Global Maximum / YAGNI
→ exact bounded correction + falsifiable proof
→ return to 4C
```

Likewise, an existing backend/API shape is not preserved merely because it already exists if a real human interaction falsifies its sufficiency. Existing counts and mechanisms are derivation results, not optimization targets.

## Layer-specific application

| Decision class | Required method posture |
| --- | --- |
| UX / IA / interaction | Frontend Product Experience Planning Method + operator structural adjudication |
| Product meaning / lifecycle / owner | Product authority Decision Loop; smallest semantic reopen |
| wire / API / DTO | exact Product consumer first; schema closure + negative controls; canonical generated custody |
| frontend state | SERVER / URL_NAVIGATION / FORM_DRAFT / EPHEMERAL_UI unless a real fifth class is proven |
| backend logic | exact owner invariant/consumer first; no generic service/domain by symmetry |
| auth / security | server-derived current authority; client visibility never grants access |
| data / persistence | owner truth and non-derivability first; no new durable record or mirror by convenience |
| SDK / framework / runtime | mechanism only after protected property; final mechanism selection remains 4D unless current proof cannot proceed without a narrower decision |
| source / Git | Project-Git authority laws first; transport/provider mechanics never become Product authority by existence |

## Stop conditions

Stop the current structural/UI path when any material interaction would otherwise require:

```text
new Product meaning not admitted upstream
new owner/trust boundary
new Permission class
new current-state or durable truth
new wire shape whose semantics are not already closed
frontend-owned authorization/business lifecycle
screen-shaped/BFF authority
parallel Product DTO/schema authority
runtime/provider mechanism promoted into authority
```

The stop is bounded: it does not reopen unrelated accepted phases or locked blocks.

## Proof rule

A decision is not accepted because it sounds coherent. Material changes require the strongest affordable proof appropriate to the layer:

```text
semantic contradiction / consumer test
schema or repository negative control
exact wire bijection / generated projection proof
adversarial alternative comparison
operator review for material Product/structure decisions
independent Fable challenge where the phase contract requires it
```

The `4C-F02` Journey-B correction is the proving example of this rule: the first source-only fix was rejected as a local maximum after broader falsification exposed missing Inception intent and durable candidate-Baseline review; the accepted bounded correction then recompiled 4A/4B and returned GREEN before W-01 structural work resumed.
