## 1. Finding

The operator falsifier is **material and partially confirmed**.

The prior C02 pass correctly kept advanced Product-Agent memory from becoming
Brain or owner authority, but its overall deferral language reinforced a wider
planning defect:

```text
Builder is the core Product mechanism
+ Budget Analyzer is the first proving Project
+ Realization Planning builds the entire proving Project without Builder
→ the first path proves app serving, not app building
```

The mistake was not rejecting a memory package. It was treating the absence of
an already-running Builder consumer as proof that the first Project need not
exercise Builder at all.

## 2. External-reference conclusion

### Mitra

Mitra's baseline is not a weak chat agent. It wraps Claude Code/Codex/OpenCode
inside E2B with versioned project instructions, persistent session, governed
tools/MCP, Git synchronization, build and share protocol. Its successful
maintenance probe shows that a strong coding loop can sustain a second turn, but
also that quality not enforced by build/schema/FK/gates varies with the model.

Transfer:

- adopt a capable coding harness from the first operational Builder;
- strengthen it with deterministic Conexus invariants;
- do not infer that a generic Agent plus prompt equals that harness.

### Factory AI

Factory's Droid, skills/hooks, sandbox, QA and Missions show that serious coding
quality comes from a runtime plus context, focused tools, independent validation
and real-system feedback. Dynamic Missions/fleets are not required for every
task, but a fresh material verifier and executable QA cannot be postponed out of
the core proof.

## 3. Current Mastra conclusion

Current Mastra provides a credible serious Builder substrate:

```text
AgentController
+ createCodingAgent or SDK/ACP-backed coding loop
+ Workspace over E2B

+ plan/build/review modes
```

verification, independent acceptance, Preview and Release.

## 6. Minimum capable Builder baseline

Required for the first operational proof:

1. `AgentController` collaborative session with exact Change/CodingSession bind;
2. persistent thread and task/goal continuity;
3. Workspace backed by E2B with the physical-incarnation guard;
4. code read/write/edit/search/command mechanics; AST/LSP admitted when the
   Worker Eval proves they improve correctness enough for their cost;
5. versioned Context Compiler output, AGENTS/skills and Paved-Road constraints;
6. plan/build plus independent review roles; not necessarily a dynamic fleet;
7. mechanical ask/approval boundary;
8. Hub-owned Git/result custody and no direct canonical push authority;
9. build/type/test/schema/browser/Preview feedback and firing negative controls;
10. current-authority rechecks, output custody, cancellation and honest failure;
11. exact model/runtime usage and diagnostic Evidence;
12. real greenfield and second-turn Worker Eval.

Not required initially:

- configurable Agent marketplace/fleet;
- generic Missions/Workflow Product owner;
- multi-agent network or arbitrary subagent graph;
- Builder Observational/Semantic/Working Memory beyond the persistent thread,
  tasks and versioned artifacts unless eval proves incremental benefit;
- PAR/Product Agents merely to implement the Builder;
- multiple production coding runtimes for optionality.

## 7. Native Mastra versus hosted coding runtime

Two candidates remain open:

### Native Mastra coding agent

Strengths: single role-isolated substrate, direct Workspace/tools/skills/tasks/
goals/controller integration, lower double-harness complexity.

Risks: beta APIs; prompt/modes/tool composition remain Conexus work; less real
maintenance Evidence than commercial coding harnesses.

### Mastra host + SDK/ACP coding agent

Strengths: reuses mature Claude/Cursor/OpenAI/Gemini/OpenCode-style coding loops,
closer to Mitra's demonstrated ceiling; Mastra can retain session/orchestration/
observability integration.

Risks: provider-specific tools/permissions/session semantics, credential and
subscription topology, double harness, weaker control of retries/context/Git,
and runtime-specific resume behavior.

Disposition:

```text
native Mastra = INCUMBENT CANDIDATE
Mastra host + SDK/ACP = REQUIRED CHALLENGER
selection = Worker Eval, not feature count
```
