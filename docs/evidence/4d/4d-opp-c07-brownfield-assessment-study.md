## 4. Required question families, not a frozen rubric

The real Project derives exact dimensions from its profile and objective. The
minimum question families are:

1. source admission/provenance and complete accessible universe;
2. languages, packages, build/test/CI, entrypoints and reproducibility;
3. APIs, schemas, migrations, configuration and external consumers;
4. module/process/dependency/runtime/deployment topology;
5. data stores, source-versus-derived truth, coverage and destructive-change risk;
6. authentication, authorization, secrets, ingress/egress and privileged paths;
7. verification, observability, recovery and known failure modes;
8. current Product/business behavior versus human objective and accepted meaning;
9. Paved-Road fit, protected/app-owned boundaries, escape prerequisites and transition risk.

These are inquiry axes. They are not a new Brownfield ontology, Product fields or
fixed PRD→BRD→architecture pipeline. A Project-specific deciding risk can add an
axis; it must not be hidden to defend a standard checklist.

## 5. Safe execution ladder

An imported repository is untrusted input. Repository instructions, package
scripts, build plugins, language servers, compiler plugins, custom grammars and
tool configuration may execute code or request network/secrets.

```text
L0 exact Git/source closure without lazy network fetch
→ L1 text/manifest/file inventory
→ L2 owner-pinned non-executing syntax/structural analysis
→ L3 isolated compiler/indexer/static analysis where exact claim requires it
→ L4 isolated build/test/runtime/database/provider proof only with explicit authority
```

For L1–L3 baseline:

- source is read-only;
- output/temp is separately writable;
- credentials and inherited environment are absent;
- network is denied unless one exact proof authorizes it;
- CPU/RAM/time/process/output budgets are bounded;
- project scripts/config/plugins are not loaded by default;
- partial/cancelled output cannot publish as complete.

L4 is not Inception convenience. It is a separately admitted real-dependency
proof and remains subordinate to the existing Builder/Data/Gateway/security owners.

## 6. Deterministic structural mechanisms

### Git plumbing

Git object/commit/tree/index/submodule/LFS closure is the required identity floor,
not an optional analyzer. A repository locator or branch label alone is
insufficient. Partial/sparse clones and missing promisor objects cannot fetch
silently during supposedly offline assessment.

**Disposition:** `REQUIRED FIRST-BROWNFIELD IDENTITY BASELINE`.

### Tree-sitter

Tree-sitter is the strongest syntax substrate candidate: local incremental CST,
error recovery, multi-language grammars and no need to execute ordinary Project
source. It provides no types, name resolution, references, dependency/call graph
or dataflow. Each grammar/external scanner/native library remains an exact
dependency and potential execution surface.

**Disposition:** `ADMIT AS SYNTAX SUBSTRATE CANDIDATE`.

### ast-grep and Semgrep

ast-grep provides polyglot syntax-aware search/lint/outline and explicit rule
tests over Tree-sitter. It is intentionally file-local and does not resolve
types/references/callees. Semgrep CE is the stronger security/structural
challenger for owner-local rules; cross-file/interprocedural coverage is a
separate current commercial-engine claim.

**Disposition:** `STRUCTURAL CHALLENGERS / CLAIM-TYPED COVERAGE REQUIRED`.

### Dependency Cruiser, Knip and Nx

Dependency Cruiser and Knip are useful narrow JavaScript/TypeScript module/
unused inventory candidates. Nx is useful when the imported repository already
has a real Nx project/task graph or that exact workspace consumer is admitted.
All can load executable Project configuration/plugins and must run isolated with
owner-controlled configuration.

**Disposition:** `NARROW PROFILE-TRIGGERED CANDIDATES / NOT UNIVERSAL`.

## 7. Semantic and deep-analysis mechanisms

### SCIP and language indexers

SCIP is the strongest open semantic-index interchange candidate for exact
definitions/references/implementations with tool/project metadata. Indexers are
language-specific, may require dependency resolution/codegen/build, and SCIP is
not a generic call/dataflow graph. Every index remains exact-revision and
indexer-version Evidence.

**Disposition:** `LEADING SEMANTIC INDEX INTERCHANGE CANDIDATE AT REAL TRIGGER`.

### Language Server Protocol

LSP is useful interactively but coverage, cache, provenance, workspace trust and
command execution vary by server. It is not a durable Evidence/index contract.

**Disposition:** `INTERACTIVE FALLBACK / NOT DURABLE ASSESSMENT AUTHORITY`.

### CodeQL

CodeQL is the deep dataflow/security oracle candidate for exact supported
language/source→sink claims. It has significant extraction/build/database cost,
language-specific coverage and separate commercial-use terms. Build-based
extraction executes repository code and must never occur outside the isolated
authorized rung.

**Disposition:** `PRESERVE DEEP DATAFLOW TRIGGER`.

### Sourcegraph

Sourcegraph combines exact code search, SCIP navigation and agentic Deep Search.
It becomes credible for cross-repository/code-host scale, compiler-accurate
navigation or repeated large-estate analysis. Enterprise topology, indexing
execution/upload, LLM egress/terms, permissions, skipped-file limits and index
freshness are material. F1 remains one canonical Project repo and has no current
cross-repo consumer.

**Disposition:** `STRATEGIC PLATFORM CANDIDATE / REAL SCALE + PRIVACY TRIGGER`.

## 8. AI-assisted understanding

The capable Builder should use bounded investigators and iterative retrieval,
not blindly stuff a repository into one prompt.

```text
lexical/source coordinates
+ syntax/symbol/dependency relations where proven
+ exact context expansion around relevant callers/config/tests
+ semantic retrieval as a measured recall challenger
→ cited hypothesis
→ owner/runtime/data adjudication
```

Embeddings/RAG help conceptual or business-language recall but are derived,
partial and freshness-sensitive. They cannot prove exhaustive reference/impact
questions. Adoption requires a gold set showing material recall gain over
`rg`/manifest/symbol/dependency baselines.

Claude Code's transferable value is agentic file/search exploration, plan mode,
isolated investigators and summarized return—not an authoritative persistent
repo map. Factory's graph + semantic retrieval and multi-trajectory evaluation
are useful challenger patterns, while proprietary claims are not selection
Evidence. Mitra reinforces progressive discovery/modernization but its public
material does not prove a general assessment mechanism.

**Disposition:** `AI = HIGH-VALUE HYPOTHESIS GENERATOR / NEVER BASELINE AUTHORITY`.

## 9. Packing, diagnostics and prioritization

Repomix is a credible bounded local source-packet candidate with includes/
excludes, token counts, Tree-sitter compression and secret checks. The packet is
a sensitive derived artifact; compression can remove behavior, secret scanning
is only a safety net and provider egress requires explicit authority.

SonarQube and CodeScene offer useful issue/complexity/hotspot/change-coupling/
knowledge-distribution Evidence. Their metrics depend on rules, history,
language/build coverage and configurable weights. Hotspot means inspection
priority, not defect; aggregate quality/health does not decide readiness.

```text
vector of claim-specific Evidence + blockers + unknowns
!= composite health/readiness/migration score
```

A score may order investigation only. It cannot approve Baseline, choose target
architecture/profile, open Change, apply scaffold, close Finding or compose
Release.

migration slice or missing proof. Material items bind exact source Evidence and
are accepted/rejected/qualified by the existing Project/domain owner.

Code expresses implemented behavior, not automatically intended Product truth.
Human intent, current business practice, live data/provider facts and existing
contracts may contradict it. Contradictions stay open; they are never averaged.

The assessment produces input to the immutable ProjectBaselineCandidate through

## 13. First-trigger comparison path

At the first real brownfield Project:

```text
identity/closure:
  exact Git + submodule + LFS + file-manifest baseline

syntax/structure:
  owner-local manifest/text checks
  vs Tree-sitter + ast-grep
  with Semgrep for named structural/security rules

semantic navigation:
  language-native/LSP baseline
  vs exact SCIP indexers
  with Sourcegraph only on scale/cross-repo trigger

deep security/dataflow:
  CodeQL only for named supported claims

AI retrieval:
  bounded lexical/symbol/graph context
  vs semantic/agentic challengers on a repo-specific gold set
```

Measure claim-specific precision/recall/coverage, exact omissions, source egress,
untrusted execution, index freshness, human correction, operational footprint,
license and migration cost. No single tool is expected to prove closure, syntax,
semantic references, call/dataflow, Product meaning and runtime truth.
