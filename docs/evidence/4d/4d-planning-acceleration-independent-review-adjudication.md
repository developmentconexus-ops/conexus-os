### 4.1 Scope consistency does not prove scope necessity

Fable observed that the current gates strongly prevent inconsistency but do not
measure “unnecessary but internally consistent” scope. The current program has
`128` operations, `117` protected properties and `24` runtime families around a
first read-only proving vertical.

**Disposition:** `PRODUCT / PLAN GAP / SURVIVES`.

Create a derived bounding map:

```text
operation ID + owner
→ first reachability R1 | RB | R2..R7 | CURRENT_LATER | NOT_INSTANTIATED
```

It owns no Product meaning, remains derived from the operation ledger and does
not replace 4F. Its purpose is scope control and an objective Godzilla measure.

### 4.2 Global pre-code Phase-4 gates over-stop incremental value

Gemini and Fable both found that the global 4E/4F/4G execution gate conflicts
with the ratified incremental-value law when applied as “plan R1–R7 fully before
any code”.

**Disposition:** `METHOD FINDING IN REPOSITORY-LOCAL PHASE-4 PROGRAM / SURVIVES`.

The Engineering Method is not reopened. The smallest owner is
`docs/phases/4-implementation-readiness-program.md` plus roadmap projection.
Each tranche must close its applicable 4D-D/4E/4F/4G before its own explicit
grant. Full-composition 4E over the Budget Analyzer Golden Flow remains due no
later than the tranche making R7/3O reachable.

### 4.3 Selection/probe sequence

Fable's independent pass asked for Keycloak/CR-1 proof before continued
selection. Gemini challenged the causal deadlock: exact real probes need selected
clients/drivers/mechanics.

**Disposition:** `DIRECTED DIVERGENCE / RESOLVED`.

```text

→ explicit operator probe grant
→ isolated exact-pin real qualification
→ scoped 4D-D/4E/4F/4G
→ separate tranche execution grant
```

Probe failure reopens only the smallest affected selection. Selection Evidence
does not masquerade as runtime proof.

### 4.4 RF-01 prerequisite inversion

Fable observed that RF-01 was selected while validation/canonicalization remained
RF-12A. That is acceptable only if RF-12A can falsify the combined BUILD cost.

**Disposition:** `LOCAL SELECTION GAP / CORRECTED`.

RF-01 now explicitly reopens if RF-12A makes the combined custom boundary
materially worse than the bounded Nx `ADAPT` alternative.

### 4.5 Status and repository custody

Fable identified mutable-status duplication and approved work living only in a
large dirty/unpushed worktree.

Not every artifact `Status` header is invalid: immutable/scoped artifact status
is legitimate. Replicating roadmap-current mutable facts without a reliable
guard is the actual defect.

**Disposition:** `LOCAL EXECUTION GAP / SURVIVES BOUNDEDLY`.

Before implementation:

- remove or guard mutable status duplication;
- create a recoverable repository checkpoint;
- preserve `.wireframe-preview/`, `PRODUCT.md` and all unowned state;
- push/PR/merge still require explicit authority.

### 4.6 Human/product learning

The repository has deep model/operator review but no operational Project yet.
The first valid consumer is internal-company/operator use, not an invented
external-customer requirement.

**Disposition:** `METHOD CORRECTION / SURVIVES BOUNDEDLY`.

Every implemented tranche ends with an internal-company user/operator
walkthrough before the next tranche expands. Runtime/user Evidence may reopen the
smallest owner.
