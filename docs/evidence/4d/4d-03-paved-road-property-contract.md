## 1. Decision

**Outcome:** `CURRENT STRUCTURE CONFIRMED / SEVEN OWNER-BOUNDED MECHANICAL CONTRACTS`.

The Paved Road is not one universal SDK, repository, store, policy engine or
runtime. It is the smallest composition of seven mechanical contracts needed to
make accepted behavior easy and protected failure classes hard:

```text
1. canonical wire + request authority
2. browser projection + interaction conformance
3. owner-isolated persistence + Project data path
4. exact integration binding + Gateway execution
5. immutable Release + MAR serving/occurrence
6. Builder/runtime/protocol composition
7. verification + evaluation + observation Evidence
```

Each contract consumes exact owner facts, performs bounded mechanics and
returns an owner-routed result or Evidence. None owns Product meaning,
authorization, acceptance, terminal truth or business data by convenience.

This candidate maps all `106` post-scaffold ledger properties. It does not
select a framework, adapter, package, version, directory, database object,
deployment unit or process boundary. The operator approved it on 2026-08-29;
4D-B is closed and only 4D-04 runtime-family applicability may now open.

## 2. Root cause and target invariant

The root defect class is repeated local implementation of cross-cutting
correctness, allowing application or framework conventions to become accidental
authority.

```text
accepted owner fact
→ one explicit mechanical boundary
→ strongest reasonable enforcement over every reachable path
→ owner result + claim-matched Evidence

mechanism state -X-> owner truth
app edit       -X-> protected-invariant weakening
generated code -X-> editable semantic authority
```

The Global Maximum is a small set of composable owner-routed contracts, not a
larger shared abstraction. Owner-specific payloads, transactions, lifecycle and
failure meanings remain differentiated.

## 5. Contract 1 — canonical wire and request authority

### 5.1 Generated operation binding

```text
canonical 4B operation descriptor
→ deterministic server binding + transport/types + consumer client projection
→ exact owner handler
```

The binding preserves operation ID, method/path, ingress surface, request/
response schema, `Problem.code`, Permission/current-state profile and admitted
carrier semantics. A handler may not widen the generated contract through a
parallel DTO, generic payload or generic executor.

Project `Ops(R)` operations are generated only from admitted Project operation
declarations and exact Release pins. There is no `{operationSlug}` dispatcher,
arbitrary SQL/request schema or caller-selected destination.

### 5.2 Request authority context

For each protected call, trusted server mechanics derive a fresh internal
context from the authenticated Conexus session and exact route subject:

```text
opaque session reference
+ current Account/Workspace/Project/app access
+ exact operation + owner coordinate containment
+ current Release/binding facts when required
→ owner-local authorization decision at the real control point
```

Client coordinates, cached disclosure, framework request context and generated
types remain references. The internal context is not a public DTO, durable
Product record or cross-owner authorization service.

### 5.3 Technical Ingress separation

Product API and protocol ingress have separate generated censuses and bindings.
OIDC callback/login and AgentRun stream mechanics cannot acquire 4A operation
identity, Permission or Product-count impact.

### 5.4 Conditional and idempotency carriers

Carriers are emitted only from the canonical operation profile. The mechanism
may transport an owner-defined ETag/precondition or idempotency key; it cannot
invent cross-resource comparison, caller-selected idempotency scope or generic
retry permission.

## 16. Strongest adversarial challenges

### A — seven contracts become seven new authorities

They own only mechanics. Each input/output is routed to an existing semantic
owner, and framework/manifest/receipt/eval state cannot settle owner truth.

### B — global planning still front-loads too much

The reachability manifest gates realization per R1/RB/R2–R7 and separates later
current consumers, preserved seams and deferrals. Absent capability is explicit,
not scaffolded as dormant breadth.

### C — a generic context or capability object recreates umbrella authority

No caller receives a universal context. Trusted code compiles an operation-
specific, owner-routed capability with only the exact facts/actions required;
storage and Gateway boundaries independently recheck it.

### D — generated clients/handlers dictate Product architecture

Generation projects the canonical wire. Feature code depends inward on that
projection; generator and framework schemas cannot widen meaning or require an
operation owner to fit a library convention.

### E — app-owned data/UI makes conformance unenforceable

Ownership permits evolution, not bypass. App source crosses generated/platform
seams whose runtime and conformance guards cover every admitted path. A real
unmet property uses the approved escape/eject contract or stops.

### F — one Evidence system becomes acceptance authority

Claim/eval manifests are immutable Evidence only. Each exact owner decides
admission/acceptance using current required Evidence; no aggregate, trace or
framework `passed` flag self-accepts.
