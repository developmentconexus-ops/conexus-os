Missão: construir o "Playground" — BI generativo por chat (Generative UI) num projeto Mitra

O produto

Seção "Playground" no portal: cada usuário cria N "estudos". Estudo = CANVAS HTML
(a análise visual) + CHAT com um agente analista, lado a lado (grid 1fr 400px,
altura calc(100vh - ~120px)). O usuário pergunta sobre os dados; o agente
investiga o banco via SQL, NARRA o raciocínio em tempo real e, AO FINAL, desenha
uma tela HTML impecável no canvas e RENOMEIA o estudo com um título da análise.
Tudo persistente (thread + conversa rica + HTML + versões) e compartilhável por
link público. Lista de estudos com criar/renomear/excluir, cards com hover.

Stack agêntica Mitra (mitra-interactions-sdk) — verdades operacionais

•
getAgentTaskMitra({create:true, agentType:'claudecode', modelId}) → sessão.
  Reabrir: getAgentTaskMitra({taskId}) (reconecta inclusive stream ativa).
  modelId ex.: 'subscription:anthropic:claude-fable-5:medium'.

•
Eventos: taskCreated (SALVE task.id no estudo imediatamente), turnStart,
  delta ({delta,kind}) — use SÓ kind==='text', tool ({tool,input}),
  turnEnd ({content}), error, statusChange. send(), cancel(),
  loadHistory().

•
⚠️ O WS agêntico SÓ aceita sessão de usuário logado (token de integração →
  "conexão fechada"). Em app publicada, agentWsUrl vem de window.__mitraEnv;
  fora, passe em configureSdkMitra({agentWsUrl}).

•
⚠️ O input do evento tool chega TRUNCADO. NUNCA use JSON.parse nele —
  extraia campos por regex tolerante: '"campo"\\s:\\s"((?:[^"\\\\]|\\\\.){1,400})'.

•
Credencial do usuário: manageAgentCredentialMitra({action:'auth',target:'claude'})
  → {authUrl, state} → usuário cola o código → {action:'connect', code, state}.
  Ofereça esse fluxo DENTRO do chat quando error mencionar credencial.

O chat — modelo de SEGMENTOS (onde mora a qualidade percebida)

•
Turno = lista ordenada {t:'md',c} | {t:'tool',label,n?,det?,t0?} — a tool
  aparece ENTRE as falas, no ponto exato. Ao chegar tool, DESCARREGUE o buffer
  de texto pendente ANTES de inserir o passo (senão a ordem mente).

•
CHAMADAS REPETIDAS da mesma tool: NÃO empilhe linhas — funda no mesmo passo
  com contador ×N (pulse com animação pop a cada incremento, re-keye o ícone),
  det = detalhe da chamada ATUAL trocando com fade, t0 = agora. Sem isso, 6
  consultas seguidas parecem travamento.

•
Detalhe do passo ativo: prefira o titulo humano (itálico, fonte natural);
  fallback = SQL truncado (fonte mono). Extraia AMBOS por regex (input truncado!).

•
Cronômetro no passo ativo a partir de ~3s (tick de 1s enquanto streaming).
•
Streaming suave: chunks são GRANDES — bufferize e drene ~max(2, len/14) chars
  a cada 24ms no último segmento md.

•
Markdown leve nas falas (negrito/itálico/código/listas/quebras), HTML escapado
  ANTES das transformações. Fala do usuário fica texto puro à direita.

•
Tool→label amigável mapeado por serverFunctionId extraído do input (mapa
  construído do registry de SFs, NUNCA IDs hardcoded); desconhecidas = nome
  limpo (strip mcp__*__). Spinner na ativa, check nas concluídas.

Persistência e F5 (thread + conversa rica)

•
taskCreated → salve TASK_ID no estudo.
•
Persista a CONVERSA RICA (JSON das últimas ~60 msgs com segmentos; tool guarda
  só o LABEL string — ícone resolve no render) a cada turnEnd E a cada mensagem
  do usuário.

•
No MOUNT do estudo (não só no 1º send!): se TASK_ID existe, reconecte a sessão
  e carregue a conversa: 1º a CONVERSA rica; fallback = loadHistory() da
  plataforma — que devolve tool calls como TEXTO CRU (mcp__...{json}):
  detecte-os (type ~ /tool/ ou conteúdo ~ /^(mcp_[\w-]+_)?[\w-]+\s*\{"/) e
  converta em segmentos de tool, JAMAIS renderize como fala. Indicador
  "recuperando a conversa…" enquanto carrega.

•
turnEnd final usa os SEGMENTOS acumulados (não o content da plataforma).
