## 1. Opening decision

The operator explicitly selected `OPEN 4D` after 4C ratification. The 4D
Decision Loop is therefore open for planning only.

The target property is:

> A new or evolving Project receives deterministic, versioned and falsifiable
> platform mechanics for repeated infrastructure concerns, while the Builder's
> legitimate degrees of freedom remain concentrated on `APP-OWNED` Product
> logic.

### Incremental-value law

Conexus is a long, complex Product, but delivery must remain incremental and
useful inside the operator's company:

```text
plan global complexity and future seams
→ build the smallest truthful operational increment
→ make it usable by a real internal consumer
→ collect owner/runtime/business Evidence
→ correct or expand the next bounded increment
```

Do not spend a long program building dormant platform breadth before useful
Product flow. An enabling foundation is valid only with an immediate named
downstream consumer. `REALIZE` means “required when its consumer becomes
reachable,” not “build every current property simultaneously.” Safety, authority,
recovery and proof obligations are never removed to make an increment smaller.

The selected planning outcome is currently:

```text
CURRENT AUTHORITY CONFIRMED AS INPUT
+ COMPILE PROTECTED PROPERTIES BEFORE MECHANISMS
+ DEFER EXACT TECHNOLOGY/VERSION SELECTION TO 4D-C
```

No material 4C/P13 Evidence currently reopens 4A, 4B, 4C or C-018. A downstream
contradiction must reopen only its smallest owner.


- server-derived scope, binding, destination, Release and authorization;
- separate Control Plane, Preview and Published Application contexts;
- exact artifact, proof, Release, Promotion and serving identities.

### 4D-B — Paved-Road Property Contract

Must map every admitted mechanism to a protected property and a real consumer:

No helper, SDK, repository abstraction, shared store or generic framework is
admitted from a name alone.


The escape hatch is not a generic plugin system and never silently waives
security, authority, wire or Release contracts.

## 9. Proof floor

Proof strength follows the claim:

```text
deterministic generation       → byte/tree reproduction + drift negative control
ownership boundary             → mutation guard + regeneration preservation proof
wire/generated consumption     → canonical-contract derivation + no-parallel-DTO guard
authorization/session          → real browser/server negative paths
DB isolation/concurrency       → real PostgreSQL roles/constraints/transactions
external integration           → controlled real dependency Evidence
runtime recovery               → restart/loss/concurrency Evidence at the owning runtime
Release/serving                → exact real served digest and conformance proof
production recovery            → first-production proof, never a DEV imitation
```

A documentation-only control, presence test, mock-only external integration or
non-firing negative control cannot close the property it names.

## 10. Stop, defer and reopen

`STOP` when a required current property lacks sufficient owner authority,
honest comparison boundary, admissible dependency behavior or falsifiable
mechanism.

`DEFER` only when no current consumer requires the capability and the seam can
be added later without duplicating authority or dismantling the selected road.

Reopen earlier authority only on material Evidence such as:

- a locked P13 interaction cannot be realized without an invented operation,
  owner, state class or authorization path;
- a current Project property cannot fit the three ownership classes;
- CR-1 cannot preserve both current-authority serialization and owner isolation;
- a real dependency invalidates an accepted trust/runtime boundary;
- a real first consumer cannot be served or recovered through current Release,
  MAR, Gateway, data or security authority.

Framework preference, package popularity, convenience, hypothetical scale and
the existence of an upstream feature are not reopen triggers.

## 11. 4D exit gate

4D may close only when all are true:

```text
4D-A scaffold + ownership exact

no duplicate/missing Product or persistence authority
no P13 structural drift

```

4D closure or one selection cannot authorize Product implementation. Every
reachable tranche still requires its applicable 4D-D/4E/4F/4G and a separate
explicit operator execution grant. Full-composition 4E remains due by R7/3O.
